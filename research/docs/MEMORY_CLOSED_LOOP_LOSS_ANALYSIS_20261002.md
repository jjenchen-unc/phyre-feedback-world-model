# Memory 為什麼仍丟掉 base 能解的題目？

2026-10-02。使用已完成 22 組實驗的原始分數與選擇紀錄分析，沒有新增訓練
或模型推論。主要對象是幾何監督 memory；比較一律使用相同 adapted probe。
原始結果：[ADAPTED_PROBE_CLOSED_LOOP_RESULTS_20261002.md](ADAPTED_PROBE_CLOSED_LOOP_RESULTS_20261002.md)。

## 先界定哪裡輸

幾何監督 memory 的平均 AUCCESS 是 0.4622，高於 base 的 0.4541；輸的是
Success@100，63.8% 對 68.0%。因此問題不是全面無效，而是部分題更快解出，
同時把另一些 base 能解的題目丟掉。

九個配對平均，每 100 題：

- 丟掉 base 原本能解的 **5.11 題**。
- 新增 base 原本不能在 100 次內解出的 **0.89 題**。
- 淨減少 **4.22 題**，與 Success@100 差距一致。

AUCCESS 的差值可精確拆解：兩者都能解的題目，其速度變化貢獻 +0.014872；
新增成功貢獻 +0.000708；丟掉成功損失 -0.007408，合計 +0.008172。
所以主要正收益是「既有可解題的速度」，不是擴大可解題範圍。

## 最直接的失敗位置：第一次修正已把成功候選推得太後面

九組共出現 46 筆「base 可解、memory 失敗」的設定×題目紀錄，涉及 11
個不同題目。它們共享模型與場景，不是 46 個獨立實驗樣本。

- 46/46 在第一次 memory 更新後，第一個成功候選的排名都比 base 更差。
- **44/46** 在第一次更新後就超出剩餘嘗試預算：如果此時固定該排序，
  不再更新 memory，它們也無法在總共 100 次內成功。
- 只有兩筆需要後續更新才從預算內掉到預算外，都是 00014:026 的不同
  seed 組合。不能把全體損害歸因於 K4 或多輪歷史累积。

例子：memory seed 0、probe seed 1；排除兩者共同的第一次失敗後，比較
相同剩餘候選中的第一個成功 action 排名：

| 題目 | Base 排名 | 第一次 memory 更新後 |
|---|---:|---:|
| 00014:376 | 25 | **786** |
| 00007:057 | 26 | **312** |
| 00007:125 | 20 | **132** |

這不是候選池沒有答案：答案還在，只是 memory 的修正使系統先嘗試大量
其他失敗 action。也不需要等到兩種方法遇到不同 support 歷史才出現，因為
此時兩者剛執行了相同第一個失敗 action。

丟失紀錄中 25 筆在 00007、12 筆在 00014、9 筆在 00000。44/46 原本由
base 在第十次之後解出，但另外兩筆 base 第 4／7 次就能解，不能說只有
晚期邊緣候選受害。

## 部署規則讓錯誤排序持續影響後面的嘗試

目前規則最多做十次 memory 更新，之後持續使用最後一次 memory 排序，
沒有退回 base。模型即使已連續失敗，後續最多 90 次仍可能沿同一個錯誤
排序往下找。例如 00014:376 的上述組合，第一次剩餘成功排名為 786，
第十次更新後仍是 778；後續 90 次不可能走到那裡。

因此需要分開兩層：第一層是 memory 給了有害修正；第二層是決策規則沒有
限制這個修正影響候選順序多久。後者可以用現有 trace 做精確反事實重播。

## 事後重播：少更新不夠，退回 base 才救得回來

以下所有策略不看未來標籤來決定何時切換。它們先沿用原策略前 k 次：
若已成功就停止；若全失敗，從第 k+1 次開始固定 memory 第 k 次更新的
排序，或改用 base 排序，並排除已嘗試 action。整體預算仍為 100 次。

這些尾段都用已保存的固定分數，沒有假裝知道未曾造訪的 memory context。
只要不再更新 memory，完整尾段選擇可由既有候選結果精確重播。Threshold
1／2／4／10 是看過總結果後做的探索性比較，未在新資料確認。

幾何監督 memory 的九組平均：

| 策略 | AUCCESS | Success@10 | Success@100 |
|---|---:|---:|---:|
| Base | 0.4541 | 46.0% | 68.0% |
| 目前 memory：最多更新十次後固定 memory | 0.4622 | 47.0% | 63.8% |
| 只更新一次，之後固定 memory | 0.4614 | 46.1% | 64.3% |
| 更新兩次，之後固定 memory | 0.4617 | 46.6% | 63.9% |
| 更新四次，之後固定 memory | 0.4619 | 47.0% | 63.9% |
| 一次失敗後改回 base | 0.4541 | 46.0% | 68.0% |
| 前兩次失敗後改回 base | 0.4697 | 48.7% | 68.0% |
| 前四次失敗後改回 base | 0.4695 | 48.7% | 68.0% |
| **前十次失敗後改回 base** | **0.4687** | **47.0%** | **68.0%** |

固定第一次 memory 排序只救回原本丟失 46 筆中的 2 筆；退回 base@10
則救回全部 46 筆。但它也失去原 memory 新增的全部 8 筆晚期成功，因此不能
只報「救回全部」而忽略完整策略結果。最後平均覆盖率恢復為原 base 的
68%，而不是把 base 與 memory 的成功集合無代價聯集起來。

這支持「持續使用有害修正是可避免的損失來源」。不證明 2、4 或 10 是
最佳 cutoff，也不保證其他資料下 fallback 必定維持 base 覆蓋率：前面多
花的嘗試可能讓 base 的晚期答案超出總預算。原有十次更新上限讓 @10 是
自然的簡單控制，但仍需獨立驗證，不能把最高的事後數字當確認性成績。

## 為何 memory 會給出這種修正？證據仍有界線

**已定位的機制：** 同一 query、同一 head、同一第一次失敗，加入 memory
就會將某些成功 action 大幅後移；不是更換 probe 或候選池才產生。

以下是目前合理、但還不能唯一確認的原因：

1. **Support 對 query 的適用性未被可靠學會。** 一個 action 的失敗與
   prediction residual，不代表它提供的修正適用所有其他 action。模型
   已有 query/action conditioning；需要驗證修正的適用性，不能誤說架構
   完全沒有看到 query，或直接宣稱它在複製 residual。
2. **訓練目標仍未直接保護成功候選的相對順序。** 幾何監督平均物件位置、
   方向和時間誤差，能改善整體幾何，但未保證少數可解 action 維持在前排。
   它確實比純 L1 減少損害，卻沒有把所有第一次更新變成正收益。
3. **Support 資料與部署選擇不同。** 續訓的 K1 是舊 base/scorer 在 support
   半池遇到的失敗；這次是適配 probe 在 1,024 候選中挑出的失敗。即使
   都只有一條 support，其內容分布仍可能不同。後續 K2～K4 又多一層差異。
   現有結果沒有把這個因素與修正適用性／目標函數分離。
4. **讀出問題沒有被完全排除。** 適配 heads 用原 R0/base 預測訓練，並未
   對新幾何 memory 重新適配。現在可以排除「只因比較用了不同 head」，
   不能排除同一 head 對不同模型 latent 的可靠度不同。

沒有證據把「記憶越多一定越差」、representation collapse、直接 residual
複製、scorer 數值問題或單一 template 特性說成唯一根因。

## 對下一步優先順序的影響

先把「何時採用 memory、何時回到 base」作為明確的控制，並在新鎖定的
場景上確認，可比立刻重做 latent 更直接檢查這個損失機制。並行研究方向
仍是同一 query 下替換 support、固定 K／頭部／模型，比較正確、無關、
空 support 的修正；不要混入不同政策歷史。

Task-centric latent 仍在既有授權範圍內，但它要證明能減少上述有害修正，
不能只用更低 latent loss 作成功判準。本輪僅完成 trace 歸因與反事實
重播，沒有新增 fallback 部署程式、訓練或新場景實驗。
