# Memory 歸因階段 A：同一 query 的 latent、幾何與排序

2026-09-30。階段 0/A 已完成：8 場景工程檢查、100 場景主量測與結果核對全部通過。目前沒有本輪執行或排隊中的工作。沒有新增訓練、模擬 rollout 或閉環成功率結果。

## 這次比較的是什麼

同一個場景、同一批 action，分別用 base 和加入 memory 的模型預測，再用同一個固定 probe 讀出物件位置，用穩定的 scorer 排序。因此可以同時問：latent 是否更接近真值、解題相關的幾何是否更準、成功 action 是否排得更前面。

使用既有 cross 的 100 個場景、4 個模板，每場景原有 1,024 個候選。Memory 接收 base 真正遇到的失敗經驗；K1 是第一個失敗，K4 是前四個失敗。所有模型拿到相同 context，評估 query 排除最多四個 support action，K1/K4 使用相同 query。這是固定候選的離線比較，不是另一次閉環評估，也不等同第一步當下完整的 query 分布。

100 場景中，27 個第一步就成功，沒有失敗 memory；主要分析另外 73 個非空 K1 場景。其中 57 個的候選池有成功 action，可計算 AUC 與成功 action 的誤差；另外 16 個仍計入整體及失敗 action 的誤差。各指標先在場景內平均，再對場景等權平均。

## 主要結果

L1 越低代表 latent 越接近真實編碼；AUC 越高代表成功 action 通常排在失敗 action 前面。幾何誤差是未來 31 個取樣時刻，預測與真實目標物件表面距離的平均絕對誤差，單位 pixel；它不是模擬器的成功判定。

| 模型 | 整體 latent L1（73 場景）↓ | 成功 action latent L1（57）↓ | 成功 action 幾何誤差（57）↓ | AUC（57）↑ |
|---|---:|---:|---:|---:|
| Base | 0.115010 | 0.131889 | 32.42 | 0.5654 |
| 原始 R0 | 0.114210 | 0.131602 | 41.23 | 0.5052 |
| A seed 0 | 0.114019 | 0.132155 | 49.88 | 0.4424 |
| B seed 0 | 0.114013 | 0.132306 | 48.83 | 0.4435 |
| A seed 1 | 0.113902 | 0.131704 | 48.01 | 0.4536 |
| B seed 1 | 0.113861 | 0.131844 | 47.89 | 0.4535 |

R0 是原始 memory 模型；A/B 是此前不同 support 資料來源的微調，兩組各有兩個微調 seed，均由同一 R0 出發，不能當成五個獨立完整訓練 seeds。

**這批 cross 資料確認：平均 latent L1 下降，不保證排序改善。** R0 的整體 L1 下降約 0.70%，成功 action 的幾何誤差卻增加約 27.2%，AUC 下降 0.0602。四個微調模型整體 L1 下降約 0.86–1.00%，但幾何誤差及 AUC 更差。

這不只是不同指標納入不同場景造成的現象：只保留相同 57 個可算 AUC 的場景，base/R0 的整體 L1 仍由 0.116264 降至 0.115240。R0 有 62/73 場景的整體 L1 下降、41/57 場景 AUC 下降；其中 39/57 場景同時出現 L1 下降與 AUC 下降。成功 action 幾何誤差在 49/57 場景增加。四個模板各自的平均 AUC 變化均為負，幅度不同，不能把四個模板當成大量獨立模板證據。

## 需要修正的先前解釋

不能把「成功 action 的 latent L1 一定變差」當成目前 cross 的通則。這次 R0 成功 action 的平均 L1 其實略降約 0.22%，35/57 場景改善；A/B seed 1 的平均也略降，seed 0 則略升。先前小型驗證集成功 action L1 變差的觀察仍然成立，但不能直接套到這批 cross。

因此，「失敗 action 太多，平均 loss 把成功 action 蓋掉」不足以單獨解釋結果。即使單看成功 action，latent 各維度平均誤差略降，也可以伴隨更差的解題幾何讀出。這支持優先研究 loss 是否保護決策重要資訊，以及 probe 如何讀取修正後的 latent；尚未分清是 latent 的重要部分被修壞，還是 probe 對模型產生的 latent 不夠可靠，或兩者交互作用。

## 其他對照告訴我們什麼

把真實 rollout 的 latent 交給同一 probe/scorer，57 場景平均 AUC 為 **0.9769**；直接把真實幾何交給 scorer，為 **0.9942**。這表示這條讀出與排序流程在真實輸入上有很高的辨識能力，瓶頸值得往預測 latent 與讀出的交界追查。但真實 latent 表現好，不能排除 probe 在預測 latent 上失準，也不能證明稍微降低 L1 就能沿路改善 AUC。這些使用真實未來的控制不能部署。

真實幾何在相同時間區間，時間加權 32 點與 125 點的 AUC 分別為 0.99408、0.99405。這個對照沒有呈現增加取樣密度能修復主要排序落差的證據；125 點仍不是每個物理 timestep，也未排除個別場景問題。原始未加權 32 點 AUC 為 0.99416，不能把改權重與加密取樣混為一談。

K4 可用的 62 個場景（46 個可算 AUC）中，固定相同場景與 query，R0 的 K1→K4 AUC 是 0.43898→0.43940，base 是 0.50095；四個微調模型的 K1→K4 變化均不到 0.0016。這些既有模型在此設定下，多給四個以內的失敗經驗沒有消除退步；不能推出 memory 數量一般無效。

## 目前可以與不可以歸因的範圍

已定位到：同一 query、共同失敗 context、穩定 scorer 下，memory 修正可同時降低平均 latent L1、損害成功 action 的幾何讀出及排序。這個現象在第一次更新就存在，不需要後續 policy 分歧才發生。

尚未證明：support residual 被直接複製、support–query 適用關係是唯一根因、資料比例或 loss 是唯一根因，或 scorer/probe 完全沒有問題。尚未執行完整方案的 oracle 修正、support 替換或 probe 適應介入；不能把本階段量測當成完整因果歸因。

下一個有辨識力的步驟是固定 query 做階段 B/C：檢查可控的預測修正是否改善幾何與排序，以及相同 K 下改換 support 經驗會怎樣。這些分支尚未啟動。所有結果來自重複使用的四模板開發資料，沒有新模板的確認性結論，也沒有以大量 action 當成獨立樣本的顯著性主張。
